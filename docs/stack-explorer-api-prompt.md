# Stack Explorer — Go REST API Implementation Prompt

Boot the `sigil-backend` agent (or a Go backend agent) and build the REST API for Stack Explorer.

## Goal

Add an HTTP server to the Stack Explorer Go CLI that serves a REST API matching the Sigil datasource contract. The frontend (a Next.js app generated by Sigil) expects these exact endpoints, field names, and response shapes.

## Project Location

- **Stack Explorer repo:** `/Users/chrispian/Projects-apps/stack-explorer/`
- **Go module:** `github.com/chrispian/stack-explorer`
- **Database:** SQLite at `data/stack-explorer.db` (via `modernc.org/sqlite`, pure Go)
- **Existing code:** CLI commands in `cmd/stack-explorer/`, domain types in `internal/domain/`, SQLite store in `internal/store/sqlite/`

## What Exists

- **14 DB migrations** with all tables created
- **Domain types** for all entities (Repo, Tag, Snapshot, Lens, ReviewDimension, Scorecard, DimensionScore, ArchitecturePattern, Finding, ComparisonSet, ReportConfig)
- **SQLite store** with CRUD operations for most entities
- **No HTTP server** — this needs to be built from scratch

## What to Build

### 1. HTTP Server (`internal/api/`)

Add a Chi router (or net/http ServeMux — Chi preferred for middleware and route groups). Create:

- `internal/api/server.go` — Server struct, router setup, middleware (CORS, JSON content type, logging)
- `internal/api/handlers.go` — One handler file per resource, or grouped by domain
- A new `serve` Cobra command in `cmd/stack-explorer/` that starts the HTTP server on port 8080

### 2. Endpoints

Every LIST endpoint must support these query parameters:
```
GET /api/{resource}?search=&filter[field]=value&sort=field&direction=asc|desc&page=1&pageSize=25
```

Every LIST response must return:
```json
{
  "data": [...],
  "meta": {
    "total": 100,
    "page": 1,
    "pageSize": 25,
    "pageCount": 4
  }
}
```

Single-item responses: `{ "data": { ... } }`
Create responses: 201 with `{ "data": { ... } }`
Delete responses: 204 no body

### 3. Exact Endpoints and Fields

**Important:** The frontend expects these exact JSON field names (snake_case). Map from Go domain types as needed.

#### Repo — `GET/POST /api/repos`, `GET/PUT/DELETE /api/repos/{id}`
```json
{ "id": "string", "name": "string", "url": "string", "description": "string",
  "stack": "string", "category": "string", "is_own": bool,
  "local_path": "string", "score": number, "loc": number, "tags": "string" }
```
- `score`: computed from latest scorecard overall (may need a JOIN or subquery)
- `loc`: from latest snapshot
- `tags`: comma-separated tag names (JOIN through repo_tags)
- Filterable by: `stack`, `category`, `is_own`
- Searchable by: `name`, `description`, `tags`
- Default sort: `name ASC`, pageSize: 25

#### Tag — `GET/POST /api/tags`, `DELETE /api/tags/{id}`
```json
{ "id": "string", "name": "string" }
```

#### Snapshot — `GET/POST /api/snapshots`, `GET /api/snapshots/{id}`
```json
{ "id": "string", "repo_id": "string", "captured_at": "datetime",
  "stars": number, "forks": number, "loc": number, "files": number,
  "contributors": number, "commits_30d": number, "complexity_avg": number }
```
- Filterable by: `repo_id`
- Default sort: `captured_at DESC`, pageSize: 25

#### Dimension — `GET/POST /api/dimensions`, `GET /api/dimensions/{id}`
```json
{ "id": "string", "name": "string", "category": "string",
  "weight": number, "description": "string" }
```
- Maps from `review_dimensions` table
- Filterable by: `category` (values: code-quality, architecture, community, operations, documentation, security)

#### Lens — `GET/POST /api/lenses`, `GET/DELETE /api/lenses/{id}`
```json
{ "id": "string", "name": "string", "description": "string", "dimension_count": number }
```
- `dimension_count`: COUNT of related lens_dimensions

#### Scorecard — `GET /api/scorecards`, `GET /api/scorecards/{id}`
```json
{ "id": "string", "repo_id": "string", "repo_name": "string",
  "lens_id": "string", "lens_name": "string",
  "overall": number, "scored_at": "datetime" }
```
- `repo_name`: JOIN repos.name
- `lens_name`: JOIN lenses.name
- Filterable by: `repo_id`, `lens_id`
- Default sort: `overall DESC`

#### DimensionScore — `GET/POST /api/scores`, `PUT /api/scores/{id}`
```json
{ "id": "string", "scorecard_id": "string", "dimension_id": "string",
  "dimension_name": "string", "score": number, "evidence": "string" }
```
- `dimension_name`: JOIN review_dimensions.name
- Filterable by: `scorecard_id`, `dimension_id`

#### Pattern — `GET/POST /api/patterns`, `GET/PUT/DELETE /api/patterns/{id}`
```json
{ "id": "string", "name": "string", "type": "string", "category": "string",
  "description": "string", "repo_count": number }
```
- `repo_count`: COUNT of related repo_patterns
- `type` values: "pattern", "anti-pattern"
- Filterable by: `type`, `category`

#### Finding — `GET/POST /api/findings`, `GET/PUT /api/findings/{id}`
```json
{ "id": "string", "title": "string", "repo_id": "string", "repo_name": "string",
  "category": "string", "severity": "string", "status": "string", "description": "string" }
```
- `repo_name`: JOIN repos.name
- Filterable by: `repo_id`, `category`, `severity`, `status`
- Searchable by: `title`, `repo_name`

#### ComparisonSet — `GET/POST /api/comparison-sets`, `GET/DELETE /api/comparison-sets/{id}`
```json
{ "id": "string", "name": "string", "subject_count": number, "reference_count": number }
```
- `subject_count`: COUNT WHERE role='subject'
- `reference_count`: COUNT WHERE role='reference'

#### ReportConfig — `GET/POST /api/reports`, `GET/DELETE /api/reports/{id}`
```json
{ "id": "string", "name": "string", "lens_id": "string", "lens_name": "string",
  "repo_count": number, "audience": "string" }
```
- `lens_name`: JOIN lenses.name
- `repo_count`: computed from filters applied to repos
- Filterable by: `lens_id`, `audience`

### 4. CORS

The frontend runs on `localhost:3334`. Add CORS middleware allowing:
- Origin: `http://localhost:3334` (and `*` in dev)
- Methods: GET, POST, PUT, DELETE, OPTIONS
- Headers: Content-Type, Authorization

### 5. Implementation Notes

- Reuse the existing `internal/store/sqlite/` layer — it already has most CRUD operations
- Add new store methods where needed (e.g., list with pagination, search, filter)
- IDs in the DB are integers — the frontend uses strings. Convert with `strconv.Itoa`/`strconv.Atoi`
- Use `encoding/json` for serialization
- Add `chi` router: `go get github.com/go-chi/chi/v5` and `github.com/go-chi/cors`
- The `serve` command should accept `--port` flag (default 8080) and `--db` flag (default `data/stack-explorer.db`)
- No auth needed — this is a local tool
